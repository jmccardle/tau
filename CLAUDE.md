# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

τ ("tau") is a Python agent harness — a programmable coding-agent library with an optional TUI. It began as a port of the TypeScript [pi-mono](https://github.com/badlogic/pi-mono) project, and a local checkout still lives at `~/Development/pi`.

**Parity with pi is not an objective** (decided 2026-09-03, at the start of the architecture overhaul). pi is a reference for how a ported behaviour was originally derived, not an authority on what τ should do; a divergence needs no justification beyond its own reasons, and "pi does it this way" is not one. Reading the corresponding pi file is still often the fastest way to understand ported code — it is not a check to pass.

## Every commit here is published

From 0.10.3 onward this history **is** the public history: commits go to
`github.com/jmccardle/tau` as they are made, unsquashed. Through 0.10.2 they did
not — development happened in a private repository and each release replaced the
public tree in one squashed commit, so a commit message was private and only the
release note was read. That is no longer true of anything written here. A commit
subject, a test fixture, a docstring and a `docs/` file are all published the
moment they are pushed, and `git push --force` is no longer a way to unsay
something.

`tau-coding-agent/tests/test_no_host_addresses.py` is what enforces the
consequence, over two surfaces with two patterns. The five `src/` trees plus
`examples/` and `scripts/` reject a LAN address and a home directory, because a
user installs or copies out of them. The prose that ships — `docs/`, `README.md`,
`ROADMAP.md`, `CLAUDE.md` — rejects a home directory and the private git host,
because there the problem is disclosure rather than breakage.
`docs/probe-results/` and `experiments/` are exempt from both: a measured
`192.168.…` there is the *record of a run*, and rewriting it would falsify the
measurement.

The private host's address appears in **exactly one place**, that test's own
constant. A document describing the leak pattern must not repeat the value.

`docs/RELEASE-NOTES-0.10.2.md` is the boundary and says what changed for a
reader; `docs/RELEASING.md` "The two repositories" is the procedure.

## Monorepo layout

Five independently-installable distributions, each `src/`-layout. The three that
carry the program stack bottom-up:

| Package | Imports as | Depends on | Responsibility |
|---|---|---|---|
| `tau-llm/` | `tau_llm` | — | Wire protocols (`openai-completions`, `anthropic-messages`, `google-generative-ai`), streaming events, message/tool types |
| `tau-agent-core/` | `tau_agent_core` | `tau_llm` | Agent loop, tools, sessions, extensions, compaction, the capability registry (headless) |
| `tau-coding-agent/` | `tau_coding_agent` | `tau_agent_core` | Textual TUI, the CLI entry points, the backends |

Two more exist and are easy to forget, which is why the pre-commit hook gates
**five** `src` trees and the install line below names **four**:
`tau-jmfts/` (`tau_jmfts`, the JMFTS client and enrichment extension, optional)
and `tau-meta/`, which builds the `ffwf-tau` distribution — a guessable name
resolving to `ffwf-tau-coding-agent[tui]`, holding one module whose only
contents are `__version__`. `docs/ARCHITECTURE.md` §1 has the sizes and the
reason that module is not empty.

Port provenance — which pi package each τ package was originally derived from, for reading history, not for matching behaviour: `tau-llm` ↔ `packages/ai`, `tau-agent-core` ↔ `packages/agent`, `tau-coding-agent` ↔ `packages/coding-agent`.

## Architecture: the streaming event pipeline

The single most important thing to understand — because it spans four files and **two distinct event vocabularies** — is how one user turn flows from HTTP bytes to rendered tool calls:

1. **`tau-llm/.../providers/openai.py` → `OpenAICompletionsProvider.stream_chat`**
   Posts to `/chat/completions` with `stream:true`, parses the SSE lines, and accumulates deltas into an `_Accumulator`. Emits **τ-llm streaming events**: `TextDeltaEvent`, `ToolCallDeltaEvent`, `DoneEvent`, `ErrorEvent` (see `tau_llm/streaming.py`). The terminal `DoneEvent.final` is the authoritative `AssistantMessage` — its `ToolCall` blocks carry the parsed `arguments` that actually get executed.

2. **`tau-llm/.../client.py → stream_simple`** is the thin wrapper the loop calls.

3. **`tau-agent-core/.../agent_loop.py → AgentLoop.run`** consumes those streaming events and re-emits a *different* vocabulary, **`AgentEvent`s** (`tau_agent_core/events.py`): `agent_start`, `turn_start`, `message_start/update/end`, `tool_execution_start/end`, `turn_end`, `agent_end`. It pulls tool calls off the final `AssistantMessage` via `get_tool_calls()`, runs them (`_execute_tool_calls`, sequential or parallel), appends `toolResult` messages, and loops until there are no tool calls or `max_turns`.

4. **`tau-agent-core/.../agent_session.py` + `sdk.py`** wrap the loop with a session + an async event bus; `_resolve_tools(names)` maps `["read","write",...]` to `AgentTool` instances.

5. **`tau-coding-agent/.../backends.py → TauBackend`** adapts the AgentSession to the `Backend.stream_chat(messages, callback)` contract by `subscribe()`-ing to the event bus, turning `message_update` text deltas into `callback(delta)` and collecting `toolCall`/`tool_execution_end` blocks for display.

6. **`tau-coding-agent/.../app.py → TauApp`** is the Textual app; it renders streamed text at 30 Hz and shows tool-call / tool-result blocks.

Key consequence: a "tool call" is transformed several times (provider `ToolCall` → loop `message` dict block `{"type":"toolCall",...}` → backend `tool_calls_info` dict → TUI widget). When tool calling misbehaves, trace the `arguments` value through all four hops; the conversion of an `AssistantMessage`'s pydantic blocks to dicts happens via `model_dump()` at the loop boundary.

## Code style

- **Docstrings carry the explanation.** Every module, class and function gets a Google-style docstring: what it is, its parameters, what it returns. Design rationale — why this shape and not another, what was measured, what was rejected — belongs in a `docs/` file, cited by name from the docstring.
- **A comment is ONE line, and it states a dependence or an assumption.** An ordering constraint, an invariant the reader cannot see from the code, a workaround tied to a named upstream version. `# rope prepends, so move in reverse` is a comment. A paragraph on why the design is the way it is, is not.
- **No multi-line comment blocks.** Every one in the tree was deleted mechanically in `cf3e30f` — 13066 lines in 2786 blocks across 368 files. A run of two or more `#` lines is a code smell: it is prose that outgrew its place, and it drifts silently because nothing checks it. Tool directives (`# type:`, `# noqa`, `# fmt:`, `# pragma:`, a shebang, a coding line) are exempt because they are code.
- **A comment is never a load-bearing interface.** `rpc/commands.py`'s "E5 in Tier B" and "DURABILITY in Tier B" blocks were: twelve `notes=` strings cite them by name and are published into `docs/RPC-PROTOCOL.md`, and a test sliced them out of `inspect.getsource`. They are now in that module's docstring. If prose must be readable from code, put it where `__doc__` reaches it.
- **Streamline the docstring of anything you touch — permission is standing, do not ask.** Editing a function, class or module means leaving its docstring shorter and more useful than you found it, in the same commit, with no separate approval. This is opportunistic and never a sweep: touch what the change already touches. Cut three things — **history** (what this used to do, which step or review changed it, what a since-fixed bug was); **restatement** (a `Returns:` line that only re-types the annotation, an `Args:` entry that only re-types the parameter name); **rationale** that belongs in a `docs/` file, which moves there and comes back as a one-line citation. Keep what a reader cannot get from the signature: the units, the failure modes, the ordering constraint, which of two similar values this one is. Aim under 20 lines; over 50 is a `docs/` page with a citation, not a docstring. The measured state on 2026-09-12 is 2059 docstrings holding 25 156 lines — **37.6% of the five `src` trees**, up from 32.5% on 2026-09-04, so the rule is not yet winning against new code. Two readers pay for that: a person scrolls past it to reach the code, and a model spends input tokens on it before it can act.
- **Short and complete beat long and complete.** `scripts/check_docs_coverage.py` counts a marked object as complete when every parameter is documented and a returning object has `Returns:` — it never measures length, so shortening a docstring cannot lower coverage and filling a missing one is the fastest way to raise it. Coverage rising and docstring lines falling are the same goal, not a trade. The end state is a short useful docstring on every marked object; it is a long-term project and progress is made one touched function at a time.
- `scripts/strip_comment_blocks.py` is the tool; it re-parses each file and refuses to write when the AST changes. `--check` writes nothing and exits 1 on any block, and `.githooks/pre-commit` runs it as a fourth gate — so this rule is now enforced, not merely stated. It can be a hard gate where the docs-coverage gate is not, because the five `src` trees hold zero blocks: it passes on a clean tree and only ever fails on something a commit just wrote.

## Conventions & gotchas

- **OpenAI streams tool-call arguments as incremental *fragments***, one piece per chunk in `delta.tool_calls[].function.arguments`; they must be **concatenated** (pi: `openai-completions.ts:363`). Any logic that treats a chunk's `arguments` as the *complete cumulative* string is wrong and will corrupt the JSON. See `docs/TOOL-CALL-PARSING-BUG.md`.
- **"Fail Early" — avoid silent fallbacks.** Per the repo owner's standing rule, fallbacks/placeholders are an anti-pattern; prefer raising over fabricating data. The fake `OPENAI_API_KEY` default and the `{"raw": <string>}` tool-arg fabrication are now fixed (the provider raises `No API key for provider: …` on a missing key, and the parser raises on a *complete* invalid payload). Stay alert for new instances.
- **A reading lives in the core; a head renders it and never computes it.** τ has three heads — the Textual TUI, `tau -p`, and `tau --mode rpc` — so a user-visible *derivation* written in `tau_coding_agent` reaches exactly one of them. This rule was derived twice independently, and the second doc says so: `docs/TRUNCATED-TOOL-CALLS.md` §3.1 closes "the same shape `PROMPT-CACHING.md` §7 closed". Both landed identically — a pure module in `tau_agent_core` (`truncation.py`, `prompt_cache.py`) holding the reading with no clock and no latch, the TUI mounting a box, `tau -p` writing to stderr because stdout is a transcript in one mode and JSONL in the other and both get redirected, and the wire carrying the FACT rather than the sentence, since a host branches on an enum and string-matches nothing. Before writing a derivation inside a head, name which of the three would not get it.
- **Documentation is part of an agent-facing change, not a follow-up.** Any object an extension author or an agent calls carries `@agent_facing(topic=...)` from `tau_llm.docs`. A marked object with an undocumented parameter fails `scripts/check_docs_coverage.py`, which the pre-commit hook runs alongside mypy and ruff. The decorator is a typed no-op — it costs nothing at runtime and the build reads it out of the AST, never by importing. Adding or changing a marked object means: write the Google-style docstring (every parameter, `Returns:` when it returns something), run `scripts/build_agent_docs.py`, and commit the regenerated `docs/library/reference/` with the change. Topics come from `docs_build.TOPICS` and a new one needs a page, not just a new string. **The gate is not in the hook yet** — the tree is at 53.8% (514 of 955 marked objects, measured 2026-09-12) and a hook that always fails is a hook people switch off. The comment-block gate went into the hook the same day *because* its tree is clean; this one goes in when its tree is. See `docs/AGENT-DOCS.md` §7 for the baseline and what remains. Those same pages are **public**: `scripts/export_site_reference.py` copies them into `../ffwfrobotics.github.io` under `docs/tau/reference/api/`, with the body byte-identical, so a docstring written here is read on the web — see §9. Exporting is not part of a commit here; it is run when the site is next published, and `--check` says whether it is due.
- **Seventeen source files cite a spec file that no longer exists.** `Reference: PHASE-N-SUBPHASE-M.md` headers are a port-era convention and `docs/PHASE-*-SUBPHASE-*.md` was retired in the 2026-08-10 docs cleanup — the citation resolves to nothing, so read it as provenance and never go looking for the file. `docs/SUBPHASE-0.0.md` is the one survivor of that naming and is live: it defines the core data contracts (Message/Tool/Event shapes) and 24 source files cite it.
- The default model in `~/.tau/config.json` is `local-llm`, pointing at a local OpenAI-compatible server (e.g. vLLM/Ollama). Local servers stream argument fragments aggressively, so they exercise the accumulation path that single-chunk cloud responses can mask.

- `docs/EXTENSION-FLOWS.md` — **built (2026-09-05).** `api.register_flow` lets an extension say what its command TAKES, so the command gets tab completion, a rendered form and a palette argument in every head with no head code naming it. Two properties carry it. §3.1: **the registry stays frozen and an extension arrives as a LAYER** — `FLOWS`/`DOMAINS`/`CAPABILITIES`/`VIEW_COMMANDS` are still module constants, `Vocabulary` is one frozen value over them, `BUILTIN` holds τ's own, and the eight pure functions that read the registry take one as a *defaulted* parameter (which is what left ~40 call sites untouched).
