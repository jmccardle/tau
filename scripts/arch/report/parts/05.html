Default status: ran trace_turn.py --variant all (~27 s, 11 variants). The script calls tau_coding_agent.cli.main with -p --mode json --model trace-model --session-dir <tmp> -e trace_turn.py -ne --no-context-files --no-prompt-templates --no-skills "<prompt>". The model is the real OpenAICompletionsProvider over an httpx.AsyncClient on a MockTransport that serves scripted chat.completion.chunk frames. Request 1: reasoning_content ×2, content ×2, two tool calls (index 0 split over two deltas), finish_reason tool_calls, a usage chunk, [DONE]. Request 2: text, stop. The tools are the seven built-ins; the turn runs read note.txt and bash echo hi (a real subprocess). The script is also the -e extension: it subscribes to every HOOK_EVENTS and LIFECYCLE_EVENTS name, every AgentEvent.type, every literal channel name and "all". Recording uses sys.monitoring (call, resume, yield, unwind, raise, handled) per task and thread, plus wrappers on bus emits, log writes, cursor and LoopPosition attributes, AbortSignal.abort, turn-lock acquire/release and create_task.

Non-ideal properties the trace shows

  1. 60 asyncio tasks per turn: a collector task per completion; one task per SSE line plus a wait task; to_thread for read; 4 tasks inside bash; 21 asyncgen finalizers.
  2. Suspended generators outlive their stream; the second stream's are closed after run_print returned and after aclose_providers.
  3. turn_lock and is_streaming disagree during an aborted turn's tail; AgentSession.is_streaming (:1261) and the ExtensionContext idle check (extension_types.py:1034) read the latter.
  4. Two cursors and two logs exist per -p run: the scratch InMemorySessionLog cursor from TauBackend.__init__ and the file-session cursor that replaces it.
  5. _record_config runs four times for a two-request turn, each a full fold; two config entries precede the user message (the first from session creation).
  6. A tool-bearing completion emits two message_end events. Each message is held in the loop's messages, writer.messages, the log, _recorded, the turn_end event and the turn_end hook payload; usage sits in cursor.last_usage and in TurnStream.
  7. Write and event order varies by kind: assistant (open → message_start; finalize → entry_written → message_end); sequential tool (end event → entry); parallel tool (entry → end event); failure (agent_end before turn_error).
  8. Conversions: argv → Submission → UserMessage → dict; fold + pydantic → convert_to_llm → system frame → OpenAI JSON; SSE → _Accumulator → partial rebuilt per delta → typed event → queue → AgentEvent (whole text each update) → stamped copy → TurnStream; ToolCall → PreparedToolCall → raw → AgentToolResult → ToolResultMessage → dict.
  9. The hook name turn_end shadows the event type turn_end (extension_types.py:2024-2036).
  10. Under --mode json, extension errors go to stdout as records (headless.py:1154-1162).

Not exercised by the trace: steer, rollback, fork, follow-ups, compaction, suspensions, policies, other turn-ending hooks raising, abort mid-stream, length cut-offs, max_turns, the repeat-call limit. Only -p --mode json was driven.
