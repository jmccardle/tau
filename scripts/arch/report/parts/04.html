What a fork copies and what it references

  • Session.fork makes one-level dict(e) copies of the entries entries_for_fork selects, ids and parentIds unchanged (ca/session_store.py:544-557). With at, the selection is the path to at plus finalized side entries whose parent is on the path or None; with at=None, every entry except open side entries (core/session_log.py:190-202).
  • Each copied line equals the source's final line for that id; first (incomplete) lines are not copied (S2 lines 8 and 12 copy S1 lines 9 and 14). The side branch e12/e13 is not copied.
  • The nested message dicts of the copies are the same objects as the source Session's in-memory entries inferred: entries_for_fork returns the log's own dicts and dict() is shallow.
  • The only cross-file link is the header parent (S2 → S1, S3 → S2). firstKeptId and configId keep resolving inside the new file; compaction, image blocks and ext annotations are copied byte-identically; the system prompt is entry e02, copied with its id.
  • In the JMFTS store, fork remaps navigate.targetId, compaction.firstKeptId and branch_summary.fromId but not compaction.configId, elide.configId or suspension.entryId: after a JMFTS fork the compaction's configId names a document of the source conversation (ran glossary storage probe).
  • copy_of (branch and paste) keeps message, summary and copiedFrom, keeps customType only for a customMessage, gives a branch_summary copy fromId: None, and drops ext and every other field (core/tree_surgery.py:449-485).
  • Names: the fork's name is main-name; the source's reads renamed-on-side, because session_name takes the newest session_info in append order. No label entry kind exists.

Crash while paused

After os._exit while paused and a reload: pending_suspensions() returns []; answering the entry's id raises SuspensionAnswerError: unknown_id; a whole-session catalog.fork raises OpenSideEntryError; the head sits on the assistant entry with an unanswered call. A new submit is accepted and the model is sent [system, user, assistant-with-call, user]. No code in tau-llm/src or convert_to_llm synthesizes the missing tool result; this run used the fake at stream_simple, so what a provider's wire conversion does with it was not exercised.
