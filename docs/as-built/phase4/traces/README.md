# Traces, Phase 4

One turn timed across Rust and Python, with the Phase 4 driver. Observations
only; nothing here was optimized. Method and capture API are Phase 3d's
(`docs/as-built/traces/README.md`); this is the same script, re-run.

## What ran

`scripts/trace_turn.py --out docs/as-built/phase4/traces --runs 30`
(unchanged). The turn: user message, one `read` tool call (the Rust base tool),
its result, a final reply; `FakeProvider` (scripted samples, no network), every
hook point on, through the tests' `Harness` and `tau.Driver`. Run once with
the session in memory (`turn.json`) and once on disk (`turn-stored.json`).
The real provider modules (`providers/anthropic`, `openai`, `gemini`, `mock`) are
not in this turn; no API was called. View a trace at <https://ui.perfetto.dev>.

Machine: shared, load average about 4 during the run. Phase 3d's numbers were
taken on a quieter machine; compare shapes, not microseconds.

## Observations

- Core is 1.7% of the in-memory turn (40 us over 15 `answer`s, 15 `next_job`s, 4
  writes); the bindings cost about 17x that (native 609 + Python 79).
- The driver reads the session through finer-grained calls than in 3d: 76
  `cursor`, 63 `tree.len`, 48 `cursors`, 28 `labels` for one two-sample turn,
  against 15 `answer`s. Each is about 1 to 2 us. `py.busy` (33 in 3d) no longer
  appears. `py.lock` count doubled (126 to 258) at about 0.3 us each.
- The `read` tool is again the largest single effect (392 us here, 203 in 3d):
  the Rust call plus the driver's task hop.
- Hooks are 1 to 4 us each with the recorder extension.
- Stored, fsync is 55% of the traced turn (3d saw 54% and 81% in two runs);
  eight fsyncs per turn, as in 3d. The store's encode and write is 3.5%.
- Untraced stored wall time on this run: 5.6 ms median, versus 7.8 ms in 3d.
