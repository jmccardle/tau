# τ 0.17.1

## Summary

- **The web client comes with τ.** `ffwf-tau` depends on `ffwf-tau-web>=0.17,<0.18`, tau-code's
  built web client (a data-only wheel, package `tau_web`). A plain `tau serve` now serves it at its
  URL, and the banner says `open: URL#token=…`. No Node and no `--web-root` are needed.
- **`tau serve --no-web`** (`HttpEdge(web=False)`) serves no client. `/` is a short page saying so,
  and the wire at `/stream` is unchanged. The banner says `for a web client: …`.
- **A broken install is reported, not hidden.** If `tau_web` is missing, the server still starts
  and serves the wire. It warns on stderr, and `/` is a help page saying the install is broken
  and how to fix it (reinstall `ffwf-tau`, or give `--web-root DIR`).
- **Versions go in lockstep.** `ffwf-tau-web` 0.17.x pairs with `ffwf-tau` 0.17.x, and the wire's
  `PROTOCOL` changes only on a τ minor bump. `ffwf-tau-web` is released first, then `ffwf-tau`.

## Fixed

- **`tau serve -d` keeps the interpreter's flags.** The detached server was re-launched without
  them, so a runtime started with `python -I` (isolated, as tau-code's bundled one is) got a server
  that imported the user's site-packages. It now starts with the same `-I` (or `-E`, `-s`, `-P`),
  `-B` and `-O`. A regression of 0.15's fix (#79).

## Upgrading from 0.17.0

- **Nothing to do** to get the client: `pip install -U ffwf-tau` brings `ffwf-tau-web` with it.
  τ's own wheel still carries no JavaScript.
- **A server that must not serve a client** is started with `--no-web`.
  - `--no-web` with `--web-root` is refused (one or the other).
  - `--no-web` with `--no-http` is refused (there is no edge to serve from).
- **`--web-root DIR`** still wins over the installed client.
- **Python.** `HttpEdge` gains the field `web` (default `True`).

## Install

```bash
pip install 'ffwf-tau>=0.17.1'
pip install 'ffwf-tau[tokens]>=0.17.1'   # with local tokenizers
```
