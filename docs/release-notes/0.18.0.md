# τ 0.18.0 (unreleased)

## Summary

- **Images in user messages.** A person can show a model an image: a client sends images with
  `input` or `send`, and `@shot.png` in a line attaches an image file. The image travels through
  the session log, the walk and the providers to a model that can see, as a tool's image has since
  0.17. The design is [D31](../design/decisions/D31-user-images.md).
- **Completion items, attributed notices, the `Commands` event.** A completion says what a list
  shows (`label`) and one line about it (`detail`); a notice says which extension spoke, about
  which cursor, and how loud; and the command forms arrive on the stream whenever they change, so
  no client polls. The design is [D32](../design/decisions/D32-protocol3-additions.md).
- **Extension start and stop.** An extension may have `async start(tree)` and `async stop()`: it
  keeps a tree handle from start to stop, runs its own tasks (`tree.spawn`), and can change its
  tools and commands while it runs (`tree.reassemble`). Extensions can now hold a server or a
  timer for the whole session.

User images and D32 change the wire, so **`PROTOCOL` is 3**. The **store version is 3** for a session
that has held a user image, and only for one (see Upgrading).

## Upgrading from 0.17

- **Clients.** A client built for protocol 2 is refused at `hello` with `ProtocolMismatch`.
  Regenerate it from `tau serve --schema`.
  - A `User` body without images is encoded as before (`{"User": "text"}`). With images it is
    `{"User": {"text": "...", "images": [{"mime", "sha256", "width", "height"}]}}`.
  - An `Input` item gains `images`, left out when empty.
  - `input` and `send` take an optional `images`: a list of at most 20, each `{"data": "<base64>"}`
    or `{"sha256": "<hex>"}`.
  - The new call `image(sha256)` answers an image's bytes as base64.
  - `complete` and `complete_line` answer an array of `{"value", "label", "detail"}` (the server
    sends all three, `null` for none), not of strings. Insert `value`; show `label` (or `value`)
    and `detail`.
  - `Notice` gains `cursor`, `extension` and `level` (`"info"`, `"warning"`, `"error"`).
  - **The schema requires every field the server always sends.** `Notice.cursor`
    (`integer | null`), `Notice.extension` (`string | null`), `Notice.level`, `Completion.label`
    and `Completion.detail` (`string | null`) are `required`, and so are `Form.extension`,
    `Form.yields`, `Parsed.extension` and `Parsed.save`, which were always sent too. A generated
    client types them without `?`. The Python defaults only build a value; the encoding always
    writes the keys.
  - A new event kind, `Commands {forms}`: first in every snapshot (before the `CursorView`s), and
    whenever the commands change (after `Labels`, before the notices). A decoder that treats an
    unknown kind as fatal must be regenerated.
- **Extensions.** `start` and `stop` are now the lifecycle's names: an extension that already had
  an attribute of either name meaning something else is refused with `DefinitionError`. Rename
  it.
- **Programs that drive a `Driver`.** `Driver.start()` and `Driver.reload(...)` are `async`:
  `await driver.start()`. `reload` stops the old extensions before it starts the new ones, and is
  refused with `Busy` unless every cursor is at rest.
- **Notice texts** lose the `attachments:`, `permissions:`, `token_calls:` and `tokens:` prefixes:
  the extension is in the notice's `extension` now.
- **The web client.** `ffwf-tau-web` 0.18 speaks protocol 3 and is released first, as for 0.17
  (D29 §9); until it is, the bundled 0.17 client is refused by a 0.18 server.
- **Sessions.** 0.18 opens 0.17 and 0.16 sessions as they are, and writes them as version 2 (as
  0.17 does) until a user image is written.
  - The first time a session holds a user image (in a message or a pending input), its file is
    marked version 3. From then on 0.17 refuses that session by name
    (`session file version 3; this build reads 1 to 2`).
  - Every other session stays readable by 0.17.

## User images

- **Sending.** `client.send(cursor, "what is this?", [tau.ImageInput.of(png_bytes)])`. An image
  the session already holds is named by its hash: `ImageInput(sha256=...)`; never by a path.
- **`@path`.** A file named with `@` whose bytes are a PNG, JPEG, GIF or WebP image is attached as
  an image. The line gains `[image @shot.png: image/png 640x480]`; the 10 kB text limit does not
  apply. `tau -p "what is @shot.png"` and the TUI need no new flag.
- **Which models.** As for tool images: a model takes them only with `"images": true`, within its
  provider's limits (D30). A model that does not take them refuses the input before anything is
  queued (`ValueError` naming why; `Refused` on the wire). An `@path` image on such a model halts
  the input with a notice saying why.
- **Limits** (fixed for 0.18): at most 20 images per input, each at most 20 MiB
  (`tau.MAX_INPUT_IMAGES`, `tau.MAX_INPUT_BYTES`). The server decodes base64 strictly and reads
  the format and size from the bytes itself; a client's claims are ignored. Anything else is
  `InvalidParams`. A body over 64 MiB on the HTTP edge is `413`, as before.
- **Prune** keeps only the newest turn's images, user and tool alike; older ones become
  `[image WxH mime]` lines.
- **The mock provider** takes images and names them in its echo:
  `[2 images: image/png 640x480, image/png 32x32]`.
- **Shown** in the TUI, the tree pane and `tau export` as one `[image WxH mime]` line per image.

## Fixed

- **`skills` also reads `.agents/skills/` and `.claude/skills/`**, in the user's home directory
  and in a trusted project (P18-05), so a skill written for Claude Code or another agent loads
  with no copy. In a project they are pinned by trust like `.tau/skills`; a symlink there is
  refused. For one name `.tau/skills` wins over `.agents/skills`, which wins over `.claude/skills`.
  A candidate for a 0.17.3 cherry-pick, with the YAML frontmatter fix (already in 0.17.3).

  `Tree.image_named`, `Body.images`; `tau.Completion` (`tau.commandline.Completion`),

  `Answer.Hooks.halted_by`, `ModelCatalog.timeouts`.

  `commandline.completions` return `list[Completion]`; `Notice(text, cursor=None, extension=None,
  level="info")`; `Cursor.tell` and `NodeHandle.tell` take `level`; `TreeHandle.send(to, text,

  `Body.User(text, images=())`, `ItemData.Input(by, text, images=())`,
  `Client.input`/`send(cursor, text, images=())`, `Session.input`/`send(cursor, by, text,
  images=())`.

## Completion items, notices, `Commands` (D32)

- **`tau.Completion(value, label=None, detail=None)`**, also `tau.commandline.Completion`. A path
  is labelled with its name and a file detailed with its size (`4.2 kB`); a model with its
  provider, context window and `images`; a cursor with its labels and where it is
  (`node 42 · busy`); a label with its cursor; a node with its kind and first line
  (`User · fix the parser…`); a command name with its description's first line and extension; a
  list item with its own label while its value is the whole list text. `detail` is one line, at
  most 80 characters.
- **`Notice(text, cursor, extension, level)`**, `tau.NoticeLevel`. `cursor.tell(text,
  level="warning")`; `TreeHandle.tell(text, cursor=None, level=...)`. τ fills in the extension
  and cursor from the handle. A halted input's notice names the hook's extension and is an
  `error`; the image rule's halt has no extension. The built-ins' notices carry their levels (an
  `@word` that names no file, a prompt cache miss and a hidden permission rule are warnings).
- **`tau.Commands(forms)`**: the command forms, whole, on the stream. The TUI no longer polls
  `commands()` and follows a reload or a new skill file at once. `Client.commands()` stays, for a
  program without a stream.
- **The TUI** shows each completion's label and detail, toasts a notice under its extension's
  name with its level's colour (an error stays up 10 s), and redraws its command list on each
  `Commands`. **trusty** shows a notice as `[extension] text`, an error in red.

## Extension start and stop (D32)

- `async def start(self, tree)` runs once, in load order, before any hook and before a client
  connects; `tree` stays live until `stop` returns. A `start` that raises or takes over 30 s
  stops `tau`, `tau -p` and `tau serve` with the extension's source and the command that starts
  without it, as a failed import does.
- `async def stop(self)` runs at shutdown in reverse load order, after the tasks the extension
  spawned are cancelled; one that raises or takes over 5 s is reported on stderr and the next one
  runs.
- `tree.spawn(coro)`: a task τ owns for the extension; its failure is an `error` notice from it.
  `tree.reassemble()`: the extension's tools and commands changed. `tree.send(to, text, images)`:
  an extension's message may carry images, held to the model's image rule at the call.
- `extensions.NAME.start_timeout` and `extensions.NAME.stop_timeout` in the config files (or
  `--set NAME.start_timeout=120`) give one extension other timeouts. They are the administrator's,
  like `order`: never an option a client can set. `tau.START_TIMEOUT` and `tau.STOP_TIMEOUT` are
  the defaults.
- `Driver.reload` stops first: the extensions that leave are stopped, then the new ones started.
  A start that fails leaves only the extensions both sets share, and says so; restarting is the
  safer way to change extensions.
