# τ 0.18.0 (unreleased)

## Summary

- **Images in user messages.** A person can show a model an image: a client sends images with
  `input` or `send`, and `@shot.png` in a line attaches an image file. The image travels through
  the session log, the walk and the providers to a model that can see, as a tool's image has since
  0.17. The design is [D31](../design/decisions/D31-user-images.md).
- **Completion items, attributed notices, the `Commands` event.** A completion says what a list
  shows (`label`) and one line about it (`detail`); a notice says which extension spoke, about
  which cursor, and how loud; and the command forms arrive on the stream whenever they change, so
  no client polls. The design is [D32](../design/decisions/D32-protocol3-additions.md).
- **Extension start and stop.** An extension may have `async start(tree)` and `async stop()`: it
  keeps a tree handle from start to stop, runs its own tasks (`tree.spawn`), and can change its
  tools and commands while it runs (`tree.reassemble`). Extensions can now hold a server or a
  timer for the whole session.

- **`/undo`, and `/clear`, `/branch`, `/tree`, `/export`.** Two new built-ins, on by default:
  `undo` takes back the last change on a branch (`/compact`, `/prune`, `/clear`, else your last
  message, which it gives back to edit; Ctrl+Z in the TUI), and `session` starts a conversation
  again in the same session with the prompt cache warm, opens a cursor here, draws the tree as
  text and exports Markdown. What `/undo` follows is a documented convention, the undo marker,
  that any extension can write; no wire change. The design is
  [D33](../design/decisions/D33-undo-and-session-commands.md).

User images and D32 change the wire, so **`PROTOCOL` is 3**. The **store version is 3** for a session
that has held a user image, and only for one (see Upgrading).

## Upgrading from 0.17

- **Behavior changes everyone gets.** The model is offered the `agent` tool (see Sub-agents are
  on by default), and `/plan` exists. Sub-agent labels are `agent:P:N`.
- **Off by default**: `bash_guard`, `router` (and `token_calls`). `tau ext enable KEY`.
- **A drop-in named `plan_mode`, `bash_guard` or `router`** (the examples copied to
  `$TAU_HOME/extensions/`) now shadows the built-in of the same key; delete the copy.

- **Clients.** A client built for protocol 2 is refused at `hello` with `ProtocolMismatch`.
  Regenerate it from `tau serve --schema`.
  - A `User` body without images is encoded as before (`{"User": "text"}`). With images it is
    `{"User": {"text": "...", "images": [{"mime", "sha256", "width", "height"}]}}`.
  - An `Input` item gains `images`, left out when empty.
  - `input` and `send` take an optional `images`: a list of at most 20, each `{"data": "<base64>"}`
    or `{"sha256": "<hex>"}`.
  - The new call `image(sha256)` answers an image's bytes as base64.
  - `complete` and `complete_line` answer an array of `{"value", "label", "detail"}` (the server
    sends all three, `null` for none), not of strings. Insert `value`; show `label` (or `value`)
    and `detail`.
  - `Notice` gains `cursor`, `extension` and `level` (`"info"`, `"warning"`, `"error"`).
  - A new event kind, `Commands {forms}`: first in every snapshot (before the `CursorView`s), and
    whenever the commands change (after `Labels`, before the notices). A decoder that treats an
    unknown kind as fatal must be regenerated.
- **Extensions.** `start` and `stop` are now the lifecycle's names: an extension that already had
  an attribute of either name meaning something else is refused with `DefinitionError`. Rename
  it.
- **Programs that drive a `Driver`.** `Driver.start()` and `Driver.reload(...)` are `async`:
  `await driver.start()`. `reload` stops the old extensions before it starts the new ones, and is
  refused with `Busy` unless every cursor is at rest.
- **Extensions: `reverse`** is now the name of the undo hook (D33 §3): an extension with an
  attribute of that name meaning something else is refused with `DefinitionError` (a `reverse`
  that is not `async`). Rename it.
- **New lines end in an undo marker.** After `/compact`, automatic compaction, `/prune` and
  `/clear` the cursor is on a `Custom` node of kind `undo` at the end of the new line, not on its
  last message; a program that read "the cursor's node is the copied reply" reads the node before
  it. Nothing is sent differently: a `Custom` node never reaches a model.
- **Two more built-ins on by default**, `undo` and `session`: `tau ext disable undo` (or
  `session`) turns either off, and nothing depends on them.
- **Notice texts** lose the `attachments:`, `permissions:`, `token_calls:` and `tokens:` prefixes:
  the extension is in the notice's `extension` now.
- **The web client.** `ffwf-tau-web` 0.18 speaks protocol 3 and is released first, as for 0.17
  (D29 §9); until it is, the bundled 0.17 client is refused by a 0.18 server.
- **Sessions.** 0.18 opens 0.17 and 0.16 sessions as they are, and writes them as version 2 (as
  0.17 does) until a user image is written.
  - The first time a session holds a user image (in a message or a pending input), its file is
    marked version 3. From then on 0.17 refuses that session by name
    (`session file version 3; this build reads 1 to 2`).
  - Every other session stays readable by 0.17.

## User images

- **Sending.** `client.send(cursor, "what is this?", [tau.ImageInput.of(png_bytes)])`. An image
  the session already holds is named by its hash: `ImageInput(sha256=...)`; never by a path.
- **`@path`.** A file named with `@` whose bytes are a PNG, JPEG, GIF or WebP image is attached as
  an image. The line gains `[image @shot.png: image/png 640x480]`; the 10 kB text limit does not
  apply. `tau -p "what is @shot.png"` and the TUI need no new flag.
- **Which models.** As for tool images: a model takes them only with `"images": true`, within its
  provider's limits (D30). A model that does not take them refuses the input before anything is
  queued (`ValueError` naming why; `Refused` on the wire). An `@path` image on such a model halts
  the input with a notice saying why.
- **Limits** (fixed for 0.18): at most 20 images per input, each at most 20 MiB
  (`tau.MAX_INPUT_IMAGES`, `tau.MAX_INPUT_BYTES`). The server decodes base64 strictly and reads
  the format and size from the bytes itself; a client's claims are ignored. Anything else is
  `InvalidParams`. A body over 64 MiB on the HTTP edge is `413`, as before.
- **Prune** keeps only the newest turn's images, user and tool alike; older ones become
  `[image WxH mime]` lines.
- **The mock provider** takes images and names them in its echo:
  `[2 images: image/png 640x480, image/png 32x32]`.
- **Shown** in the TUI, the tree pane and `tau export` as one `[image WxH mime]` line per image.

## Fixed

- **`skills` also reads `.agents/skills/` and `.claude/skills/`**, in the user's home directory
  and in a trusted project (P18-05), so a skill written for Claude Code or another agent loads
  with no copy. In a project they are pinned by trust like `.tau/skills`; a symlink there is
  refused. For one name `.tau/skills` wins over `.agents/skills`, which wins over `.claude/skills`.
  A candidate for a 0.17.3 cherry-pick, with the YAML frontmatter fix (already in 0.17.3).
- **`/compact` and `/prune` keep the whole system prefix.** A model chosen before the first message
  put a `Config` between the session's `System` node and the skills list, and the new line hung
  under the first `System` node: `/compact` dropped the skills list from the requests after it,
  and `/prune` copied it onto the new line, past the prompt-cache prefix. The
  prefix (`prefix_length`) now runs to the last `System` node before the first message, with any
  `Config` among them; `/clear` uses the same rule.
- **`/config NAME` with no options writes nothing**, where it wrote an empty `Config` node.

## Plan mode, the bash guard and the router

Three extensions that began as experiments in `examples/speculative/` are built in. Their modules
and friction logs left that directory (the report there says what became of each wish).

- **`plan_mode`: on by default, inert until `/plan [task]`.** The branch goes read-only: the model
  is briefed once, offered only `read`, `grep`, `find` and `bash` for a short list of read-only
  commands, and refused anything else; when its reply ends the plan, the person approves, revises
  or rejects it. The mode is the option `plan_mode.mode`, so it is a `Config` node: it follows the
  branch, survives a reload and `go_to`. Nothing is shown, written or sent while it is `act`.
  Unlike the experiment, `find` is read-only, and **what counts as read-only is fixed in the
  extension, no longer an option**: a client may configure the mode, not widen the lists
  (`/config plan_mode allow_bash=...` is now an error). A drop-in named `plan_mode` shadows the
  built-in for anyone who needs other lists. `agent` is not offered in plan mode, since a sub-agent
  is offered every tool.
- **`bash_guard`: off** (`tau ext enable bash_guard`). Asks `reject | allow | always | truncate`
  before a `bash` call that tends to print a lot. Its options are `patterns` (the built-in ones are
  the default, so `/config bash_guard` shows them, and a pattern with a comma is typed as a JSON
  array), `allow`, `unattended` and `wait`. A refusal now says "nobody answered" where it said
  "nobody was there", since an `ask` cannot tell a decline, an abort, a timeout and no client apart.
  An abort never runs the command, whatever `unattended` says (tested).
- **`router`: off** (`tau ext enable router`). `!model text` and a `when`/`use` table choose the
  model for a turn. It reads the current model from `cursor.model()` and the configured ones from
  `cursor.models()`, so it no longer folds `Config` nodes to find them.

What the experiments asked of τ and is built since: `subject.tools`, `cursor.show`,
`CursorView.model`, list option defaults and JSON arrays in `/config`, `/plan add retry` with no
quotes, `NodeHandle.save_options`, a question asked on an aborted step declining at once. What is
still open, and documented in `examples/speculative/REPORT.md`: `ask` cannot say why it returned
`None`, an `OpenQuestion` does not name its call, one question's `always` does not close its
siblings' questions about the same pattern, a revise needs two questions, and `bash_guard`'s
rewrite is visible in the tree only as the note at the head of the result.

## Sub-agents are on by default

`agents` leaves `OFF_BY_DEFAULT`: a session offers the model the `agent(task, to=None)` tool unless
`load: {agents: false}` (`tau ext disable agents`). What that changes for every session:

- **The cost.** One more tool in every request: about 540 bytes of JSON (roughly 130 tokens) that
  the prompt cache keeps after the first request. A model that never calls it pays that and
  nothing else. A model that does spawns real samples, counted by `/usage` and the spending limit.
- **What a sub-agent may do.** It is offered every tool but `agent`, or the `agents.tools` option's.
  Permission rules, the step limit and the other extensions' hooks apply to it as to any cursor.
  Its calls run in your working directory like the main cursor's: a project that does not want a
  model to delegate turns the extension off.
- **Hosts and scripts.** `tau -p` and every frontend offer `agent` by default now; a test that
  counted the offered tools counts one more. `tau ext list` shows `agents` as `on`.
- **Plan mode** refuses `agent` (it is not a read-only tool).

## Conventions

[`docs/guide/conventions.md`](../guide/conventions.md) documents what a client may rely on that is
not protocol.

- **CV-02, usage.** `Assistant.meta.usage` is the contract for a reply's tokens (`input`, `output`,
  and `cached`, `written`, `written_1h`, `reasoning`, `tool_prompt` when reported; every part at
  most its whole), and the guide says which replies count. Cost needs prices only the server has:
  **`/usage json`** (`client.run(cursor, "usage", {"format": "json"})`) answers
  `{"models": [row...], "total": row, "cost_complete": bool}`, with each cost an exact decimal
  string, or `null` for a model with no price.
- **CV-04, sub-agent parentage.** **A sub-agent's label is now `agent:P:N`**, `P` the id of the
  cursor whose call opened it and `N` counting that cursor's agents from 1 (it was `agent:N`,
  counting the session's). A client groups children under a parent by reading the label. The
  model sees the new label in results (`agent:0:1 answered:`) and uses it as `to=`. A session
  that already holds an `agent:N` cursor from 0.17 keeps that label, and `to="agent:N"` still
  continues it; only new agents get the new form.

## Undo and the session commands (D33)

- **`/undo [priority] [at=NODE] [format=json]`** walks back from the cursor to the nearest undo marker
  (`/compact`, `/prune`, `/clear` write them), or to just before the last message (edit-last), and
  moves the cursor there as a go-to does. It answers `undid /compact: back to node 41`, or for the
  last message `back to node 12, before your message:` and the message; `format=json` (as
  `/usage`'s) answers
  `{"from", "to", "marker", "label", "user"}` with `user.text` to refill an editor. `at` refuses if
  the cursor moved, so two clients undo one change once. A busy cursor refuses it (`Busy`). It
  never starts the model: a cursor left mid-turn halts its step (`halted: /undo left the cursor at
  node N, mid-turn: step to carry on from there`).
- **The undo marker** (`docs/guide/conventions.md`): a `Custom` node of kind `undo`,
  `{"label", "return_to", "reverses", "priority", ...}`, written by the extension that made the
  change. `tau.UndoMarker` writes and reads it. A `move` marker (the default) is reversed by the
  move; any other priority (`file`, for checkpoints) only by `/undo <priority>`, through the
  owner's `async def reverse(self, cursor, marker)` (`Cursor.reverse`), and a plain `/undo` passes
  over it.
- **`/clear`** hangs a new line under the end of the session's system prefix, where `/compact` and
  `/prune` hang theirs: one `Config` first if the branch's model or options differ from the
  prefix's, then the marker. One root; the first request
  after it is the same bytes as a new session's (tested through the OpenAI, Anthropic and Gemini
  request builders). **`/branch [label]`** opens a cursor here (a label another cursor has is
  refused). **`/tree [at]`** draws the tree as text, a node summary per line. **`/export [path]
  [thinking]`** writes the walk as Markdown (`tau export`'s, without its header; an existing file
  is refused, and a write that fails says why). No `/new`: that is a client's
  move (Ctrl+N).
- **The TUI**: Ctrl+Z on an empty editor runs `/undo` when `undo` is loaded and the cursor is at
  rest (the message back in the editor, an undone change a toast), and a typed `/undo` does the
  same; otherwise it is the client's edit-last, as before. The transcript shows an undo marker by
  its label. trusty and the web client need nothing: the slash lines pass through.

## Completion items, notices, `Commands` (D32)

- **`tau.Completion(value, label=None, detail=None)`**, also `tau.commandline.Completion`. A path
  is labelled with its name and a file detailed with its size (`4.2 kB`); a model with its
  provider, context window and `images`; a cursor with its labels and where it is
  (`node 42 · busy`); a label with its cursor; a node with its kind and first line
  (`User · fix the parser…`); a command name with its description's first line and extension; a
  list item with its own label while its value is the whole list text. `detail` is one line, at
  most 80 characters.
- **`Notice(text, cursor, extension, level)`**, `tau.NoticeLevel`. `cursor.tell(text,
  level="warning")`; `TreeHandle.tell(text, cursor=None, level=...)`. τ fills in the extension
  and cursor from the handle. A halted input's notice names the hook's extension and is an
  `error`; the image rule's halt has no extension. The built-ins' notices carry their levels (an
  `@word` that names no file, a prompt cache miss and a hidden permission rule are warnings).
- **`tau.Commands(forms)`**: the command forms, whole, on the stream. The TUI no longer polls
  `commands()` and follows a reload or a new skill file at once. `Client.commands()` stays, for a
  program without a stream.
- **The TUI** shows each completion's label and detail, toasts a notice under its extension's
  name with its level's colour (an error stays up 10 s), and redraws its command list on each
  `Commands`. **trusty** shows a notice as `[extension] text`, an error in red.

## Extension start and stop (D32)

- `async def start(self, tree)` runs once, in load order, before any hook and before a client
  connects; `tree` stays live until `stop` returns. A `start` that raises or takes over 30 s
  stops `tau`, `tau -p` and `tau serve` with the extension's source and the command that starts
  without it, as a failed import does.
- `async def stop(self)` runs at shutdown in reverse load order, after the tasks the extension
  spawned are cancelled; one that raises or takes over 5 s is reported on stderr and the next one
  runs.
- `tree.spawn(coro)`: a task τ owns for the extension; its failure is an `error` notice from it.
  `tree.reassemble()`: the extension's tools and commands changed. `tree.send(to, text, images)`:
  an extension's message may carry images, held to the model's image rule at the call.
- `extensions.NAME.start_timeout` and `extensions.NAME.stop_timeout` in the config files (or
  `--set NAME.start_timeout=120`) give one extension other timeouts. They are the administrator's,
  like `order`: never an option a client can set. `tau.START_TIMEOUT` and `tau.STOP_TIMEOUT` are
  the defaults.
- `Driver.reload` stops first: the extensions that leave are stopped, then the new ones started.
  A start that fails leaves only the extensions both sets share, and says so; restarting is the
  safer way to change extensions.
