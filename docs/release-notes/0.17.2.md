# τ 0.17.2

A fix release: the TUI no longer crashes on replies with several tool calls when it falls behind.
The wire protocol, the store and the Python API are unchanged, apart from one new exception.

## Fixed

- **The TUI crashed with `KeyError` in `ChatDisplay.live`** during replies of several parallel
  tool calls. A client that falls behind the server's stream has some of a reply's live events
  dropped, and the drop could take a call's `CallNamed` but keep its `CallArgs`. The TUI then drew
  arguments for a call it had never been told about. Text could likewise be drawn with a hole in it.
  - Once a reply's live event is dropped for a client, the rest of that reply is dropped too. A
    slow client hears a clean prefix of each reply, and the whole reply arrives when it is saved.
  - Arguments for a call that was never named are now a broken stream, not a slow one.
    `SessionView.hear` raises `tau.tui.LiveOutOfOrder`. The TUI shows the error as a toast and
    draws the reply when it is saved, instead of crashing.
  - Choosing the cursor already in view from the tree screen dropped its live state, so the next
    call arguments hit the same `KeyError`. The live state is now kept.

## Upgrading from 0.17.1

- **Upgrade the server and the clients.** The drop rule is in the server, and the TUI's checks are
  in the client.
- **Python.** `tau.tui` exports `LiveOutOfOrder`.
