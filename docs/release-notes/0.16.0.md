# τ 0.16.0 "Trusty"

## Summary

τ is an agent harness. It runs a conversation between you, a language model and tools, and keeps
each session as a tree of nodes that you can branch, continue and share. 0.16 is a ground-up
rewrite of 0.15, not an update. A sans-IO Rust core holds the tree and the step algorithm. A
Python driver runs providers, tools, hooks, extensions and the frontends (the terminal UI,
`tau -p` and `tau serve`). Nothing was carried over from 0.15's harness: its behavior was read,
written as tests, and built again. The design is in `docs/design/`.

The package is `ffwf-tau` and installs the `tau` command. Python 3.12 or later is required (0.15
needed 3.11). Below 1.0, interfaces may change between minor versions.

## Upgrading from 0.15

0.16 is not compatible with 0.15 data or code.

- **No session converter.** 0.16 ignores 0.15 session files. A session is now a directory under
  `$TAU_HOME/sessions` with a checksummed log, not a JSONL file. If you keep 0.15 on the same
  machine, move its home aside before the first run, for example `mv ~/.tau ~/.tau-0.15`. 0.16
  then starts from a clean `~/.tau`. To keep using 0.15, point `TAU_HOME` at the moved directory.
  The hotfix branch for 0.15 is `0.15.x`.
- **No extension shim.** The 0.15 extension API is gone, with its lifecycle hooks and its
  authorization store. Extensions must be ported to 0.16's hooks (`pre_input`, `pre_sample`,
  `pre_reply`, `post_reply`, `pre_tool`, `pre_result`, `post_result`, `pre_step`, `post_step`).
  See [extensions](../guide/extensions.md) for the API and the mapping from 0.15 names.
- **Config changes.**
  - A model names its `provider` (0.15 named it differently). Models are grouped under a
    vendor group (`base_url`, `api_key_env`, `provider`) and named `group:name`.
  - There is no implicit API key discovery. A model names its variable with `api_key_env`, or
    gives a literal `api_key` (a literal warns). A hosted provider without a key fails
    `tau config check`. A 0.15 config with no `api_key_env` will not work as it stands.
  - 0.16 ships no sample models. `examples/config.json` is a sample.
  - `cost` is now `usage.price` on the model, in USD per million tokens, with all four fields
    (`input`, `output`, `cache_read`, `cache_write`).
  - `--max-turns` is the `step_limit.limit` option (`--set step_limit.limit=N`). `--ext-config`
    is `--set EXTENSION.FIELD=VALUE`. `--ui-defaults` is `--answer EXTENSION[:TEXT]=VALUE`.
  - `--thinking` is gone. Reasoning settings are provider `options`.
  - The `theme` key is `{"tui": {"theme": ...}}` in your user file.
- **Extensions and prompt files in a project load only after `tau trust`.** A discovered
  extension that fails to load stops the start. 0.15 carried on.
- [Configuration](../guide/configuration.md) describes the layers and `tau config check`.

## Highlights

Core and sessions

- Sans-IO Rust core: a tree of nodes, cursors that each sit at a node, branches, re-run, and
  `go_to`. The core does no IO and is held by property tests.
- Durable, checksummed session log. A torn tail is cut on open. One writer per session, held by
  a lease.
- `--fork REF[:NODE]` copies a walk into a new session. `tau sessions` lists, names and finds
  sessions. `tau export` writes deterministic Markdown.
- Free-threaded Python 3.14t is supported and tested.

Providers

- OpenAI-compatible servers (llama.cpp, vLLM, gateways), Anthropic and Gemini.
- Prompt cache marks for Anthropic (`options.prompt_caching`, on by default).
- Replies carry normalized `usage` and the raw usage. A provider may return chosen response
  headers in `meta`.

Tools

- Base tools in Rust: `read`, `write`, `edit`, `grep`, `find` and `bash`. Writes are atomic.
  `edit` keeps CRLF and a missing final newline. Output is capped at 10 kB, with the rest in an
  overflow file.
- Function tools from a Python signature. Tool progress reaches every client.

Standard extensions (built in)

- `retry`: wraps every provider. Off with `tau ext disable retry`.
- `compaction`: `/compact`, plus a soft and a hard limit from the model's `context_window`.
  `/prune` shortens old turns without a model.
- `usage`: cost and token counts in the status line, `/usage`, a notice when the cache is not
  being read, and a spend cap (`max_usd`) that refuses new input and halts a tool loop.
- `permissions`: `ask`, `allow` and `deny` rules. It asks nothing until configured.
  `tau -p --answer permissions=yes` answers for a headless run.
- `skills`, prompt templates and `@file` attachments.
- `agents`: sub-agents as cursors in the same process. Off until `tau ext enable agents`.
- Hook order is set per hook, and a model's config holds a section for each extension.

Frontends

- `tau`: a terminal UI (Textual) with a tree view, a session picker, forms for `/config` and
  `/model`, themes, and a window over long sessions. Ctrl+R and Ctrl+T fold thinking and tool
  boxes.
- `tau -p`: one message in, the last reply on stdout. Exit codes are 0, 1, 2, 3 (stopped before
  finishing) and 130. `--json` prints the wire's events.
- `tau serve`: one server per session on a Unix socket, speaking JSON-RPC. `tau serve --schema`
  prints the JSON Schema. `tau`, `tau -p` and `tau -r` attach to a held session on their own.
  `examples/ratatui/` is a Rust client built from the schema.

Counting and diagnosis

- Token counts follow the server's own `usage`. Nothing is estimated from characters.
- New second wheel `ffwf-tau-tokens`: local tokenizers and chat templates, installed with the
  `tokens` extra. The `tokens` built-in learns a per-model heuristic from the server's reports.
- `tau trust` pins project config, `.env`, extensions, prompts and skills by content hash.
  `tau config check` validates the config. `tau.trace` writes a Chrome trace across Rust and
  Python.
- The public API is generated from code: `docs/api/surface.txt` and [the guide](../guide/README.md).
  Start with the [quickstart](../guide/quickstart.md).

## Platforms

Wheels are `cp312-abi3` (any GIL build from 3.12) and `cp314t` (free-threaded 3.14), for each of:
Linux x86_64 and aarch64, macOS arm64 and x86_64, Windows x86_64. Each wheel is installed in a
clean environment and tested on its platform before release.

- **Linux and macOS:** everything, with the `bash` tool at parity.
- **Windows:** builds and imports, and has the core, the store, `tau -p`, the terminal UI and the
  five other base tools. Not ported, each failing with an error that names the platform:
  - the `bash` tool (`base_tools()` returns five tools there);
  - `tau serve` and its clients (the wire is a Unix socket);
  - projects (`.tau/`), because the owner and mode checks are not ported;
  - path patterns in permission rules (for example `read:GLOB`). The bare tool name works.
  On Windows, `@file` treats a backslash as a directory separator, and it escapes only a space.
  Tests of the missing pieces are skipped there, each with its reason.

Open decisions for Windows: a shell tool, a transport for `tau serve`, project trust, and how
permission patterns meet drive letters, `\` and case.

## Dropped from 0.15

On purpose, with no replacement planned:

- The REPL (the terminal UI and `examples/chat.py` cover it), the `ls` tool (use `bash`), and
  `--fun`.
- Steering and queueing of input while the model runs. Enter sends, and the line waits for the
  next step.
- The 0.15 extension API, its lifecycle hooks, locks, annotations and the authorization store.
- The step debugger and its pause UI. Turning auto-step off and answering a question remain.
- A unified `--thinking` level. Tolerant JSON repair of tool arguments: bad arguments go back to
  the model as an error.
- The `ffwf-tau` command name. Only `tau` is installed.
- Panels, `tau serve --listen` (TCP) and `--connect`. Attaching is automatic.

Regressions we accept for now, not planned for a release:

- The prompt cache dialect for an Anthropic model behind an OpenAI-compatible gateway. Such a
  gateway is billed without cache marks unless `extra_body` carries them.
- A model's own compaction settings. They are set for the session, a branch or your config.
- Latency collection and run manifests from 0.15's research tooling.

## Deferred (after 0.16.0)

- **JMFTS replica**, with the Tectum contract (the protocol over stdio, and `--no-tools`). The
  0.15 JMFTS store, importer and tools are not in 0.16. This is an accepted regression, and it
  comes after this release.
- tau-code (web and VS Code clients, a web client served over TCP) and tau-search, ported to 0.16.
- Image input, constrained decoding, a models.dev catalog command, background tools, code mode,
  the NATS bus, HTML export, the llama.cpp telemetry strip, `serve --tail`, a Docker image, and a
  screenshot harness for the terminal UI.
- Commands or extensions for elide, commit-branch, paste-subtree and compare.
- Per-run tool lists (`--tools`, `--no-tools`). Today `tau ext disable base_tools` drops the base
  tools.
- Windows gaps listed above, and a macOS `powershell` tool.
- Sequential tool mode, `summarize_and_navigate`, automatic pruning, and extension and tool lists
  in the terminal UI.

## Install

```bash
pip install 'ffwf-tau>=0.16'
```

For local tokenizers (`ffwf-tau-tokens`, a second wheel pinned to the same version):

```bash
pip install 'ffwf-tau[tokens]'
```

Then follow the [quickstart](../guide/quickstart.md).
